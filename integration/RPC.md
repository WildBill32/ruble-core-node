# Integration RPC reference

RPC is Bitcoin Core-style JSON-RPC exposed by Ruble's operator node. Use the
node's own `help <method>` for exact arguments supported by the selected build.
The public wallet build intentionally has a different RPC surface.

| Purpose | Methods |
|---|---|
| Readiness | getblockchaininfo, getnetworkinfo, getindexinfo |
| Chain lookup | getblockcount, getbestblockhash, getblockhash, getblock, getblockheader |
| Transactions | getrawtransaction, decoderawtransaction, sendrawtransaction |
| Wallet | createwallet, loadwallet, listwallets, getwalletinfo |
| Deposit address/validation | getnewaddress, getaddressinfo, validateaddress |
| Wallet activity | listsinceblock, gettransaction, listunspent |
| Fee policy | estimatesmartfee, getmempoolinfo |
| Withdrawals | sendtoaddress or walletcreatefundedpsbt/walletprocesspsbt/finalizepsbt |
| Native pool | getmininginfo, getblocktemplate, submitblock |
| Optional AuxPoW | createauxblock, submitauxblock; wallet convenience getauxblock |

Read-only examples after configuring CLI access:

```bash
ruble-cli getblockchaininfo
ruble-cli getnetworkinfo
ruble-cli getblockhash 0
ruble-cli getblockhash 1
ruble-cli help getblocktemplate
ruble-cli help listsinceblock
```

For multiple loaded wallets, specify `-rpcwallet=<wallet-name>` or use the
`/wallet/<URL-encoded-wallet-name>` HTTP endpoint for wallet methods.
Cookie authentication requires matching OS permissions and data directory.
Alternative `rpcauth` credentials are generated by the operator, never supplied
by the coin owner. Do not log Authorization headers or credentials.

`getblockchaininfo` includes `auxpowblocks`, `auxpowactivationheight` and a
`finality` object (`enabled`, `depth`, `finalized_height`, `finalized_hash`).
Some fields are conditional; validate JSON types and field availability.

`getrawtransaction` for arbitrary historical transactions may require a synced
`txindex` or an explicit block hash. `gettransaction` is wallet-specific.
Avoid raw-block parsers that blindly treat every full Ruble header as only 80
bytes: AuxPoW blocks carry additional proof data. Prefer decoded node RPC for
exchange integration.

Submission results differ: `submitblock` normally returns JSON `null` for
acceptance or a status string, whereas `submitauxblock` returns a boolean and
can raise an RPC error. Neither result replaces an active-chain check before
reward crediting. Both interfaces require a connected, synchronized node for
normal pool operation; a restarted AuxPoW node also needs fresh candidates.
